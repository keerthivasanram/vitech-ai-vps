AI Engineering Platform — Architecture & Workflow

An engineering assistant that turns a client requirement into a specification, a general-arrangement drawing, a bill of materials and a budgetary quotation — all from one deterministic engineering model, with every number traceable to a rule, a standard or a named historical project.

Current as of 2 August 2026 · 3 live agents · 14 equipment categories · 33 historical offers · 8 test suites green
The rule the whole system is built around. Numbers are deterministic. Every dimension, capacity, count, material and price is produced by engineering rules, client standards or historical data in code. The language model routes requests and writes prose — it never invents a number. Where the engineering cannot answer, the platform says so explicitly rather than filling the gap.

1System architecture

Four layers. Flowise orchestrates conversation; Python owns all engineering; the browser only renders.

Ollama serves llama3.1:8b to Flowise only. It never touches the engineering core — the link between them is a tool call carrying a requirement in and structured numbers out.

2Engineering workflow

One requirement, one resolved model, four documents. Every stage is deterministic and every output is a reviewed draft, never an auto-sent document.

The fan-out is the point: specification, drawing, BOM and quotation are four readings of one resolved model, so they cannot disagree with each other.

3What is generated and what is computed

GENERATIVE The model handles

  • Reading a requirement into intent and parameters (with a deterministic regex fallback)
  • Choosing which tool to call, and asking for missing inputs
  • Narrating results and answering general engineering questions
  • Ordinary conversation, kept in scope

DETERMINISTIC Code handles

  • Every dimension, airflow, capacity, count, weight, material and price
  • Component selection from real catalogues (203 blower models)
  • All drawing geometry, scale and dimensioning
  • Validation, size-gap checks and the release status
  • BOM quantities and every costed line
Where the boundary is enforced. Tool responses carry pre-formatted strings (price_display, spec_markdown, lookup_markdown, drawing_markdown) that the agent prints verbatim, so it never re-types a number. The drawing tool strips the SVG before returning — vector data in an 8B context wrecks the reply, and the canvas already has the drawing. Structural fixes like these have consistently proved more reliable than prompt wording.

6How correctness is held

Golden snapshots

Ten cases captured byte for byte. Any engine change must leave them identical, or the movement is explained case by case before it lands.

Eight suites

golden, engineering, drawing, lookup, pricing, retrieval, review, bom. All must pass before anything is committed.

Render, do not read

Generated graphics are rasterised and inspected. Every drawing bug found so far looked perfectly correct in the markup.
